# 从零搭建旋转花：Mac 本地 Codex → ESP32 → 电机

这是一份给 DIY 初学者的**电子和软件原型教程**。完成后，本地 Codex 任务运行时，电机会按推理强度切换档位；任务结束后停止。你可以先只让电机轴转起来，再设计自己的花朵外形。

> 适用范围：已在一台 macOS 电脑、本地 Codex 任务、ESP32-C3 SuperMini、ULN2003 驱动板和 5 V 28BYJ-48 电机上短时验证。花瓣、花盆和电机固定件还没有可直接打印的定稿文件。本教程不保证不同电脑、开发板或电机装配得到相同转速。

## 1. 准备材料

| 材料 | 数量 | 用途与选择 |
| --- | --- | --- |
| Mac 电脑，已安装并可运行本地 Codex | 1 台 | 运行 Python 桥接器并通过 USB 连接开发板；本教程未验证 Windows。 |
| ESP32-C3 SuperMini 开发板 | 1 块 | **这块板就是单片机／控制器**，不需要另买一块单片机。确认板上有 `5V`、`G` 和 GPIO4–7 标识。 |
| ULN2003 驱动板 | 1 块 | 接收 ESP32 的四路控制信号，驱动下面的五线步进电机。通常与电机配套出售。 |
| 5 V 28BYJ-48 五线步进电机 | 1 个 | 当前装配使用约 1:16 减速比版本，五档联动已短时验证。其他减速比也可能转动，但输出速度不同。购买时核对铭牌为 **5 V**。 |
| 母对母杜邦线 | **6 根** | 4 根连接 IN1–IN4，另 2 根连接电源正负。若你的板子不是公排针，应按实际接口更换线型。 |
| USB-C **数据线** | 1 根 | 从 Mac 连接 ESP32-C3，兼作当前原型的供电和串口通信。电脑没有 USB-C 口时，需与实际端口相配的线或转接器。 |

电机自带的五针插头直接插入 ULN2003 驱动板的五针插座，不计入上面的 6 根杜邦线。还需要 Arduino IDE、Espressif 的 Arduino-ESP32 开发板支持包，以及 Python 3.9 或更新版本；桥接脚本仅使用 Python 标准库。

当前只是短时验证的 USB 供电原型。不要把 5 V 电机接到 ESP32 的 3.3 V 引脚；换电机、增加负载或使用外部电源时，需要重新核对供电能力、极性和共地。接线前先拔掉 USB。

## 2. 接线

**USB 断开时**，按开发板和驱动板上的实际丝印逐项核对：

| ESP32-C3 SuperMini | ULN2003 驱动板 |
| --- | --- |
| `5V` | 电源 `+` |
| `G` / `GND` | 电源 `-` |
| `GPIO4` | `IN1` |
| `GPIO5` | `IN2` |
| `GPIO6` | `IN3` |
| `GPIO7` | `IN4` |

把电机的五针插头插入驱动板对应插座。连接完成、确认没有接反或短路后，再用 USB-C 数据线连接电脑。旋转件要固定牢靠，并与周围零件留出间隙；初次测试先不要安装较重的花瓣。

## 3. 给 ESP32 上传程序

1. 安装 Arduino IDE。按 [Espressif 官方安装说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html)添加 Arduino-ESP32 开发板支持包；本项目曾用 **3.3.11** 验证。若安装了其他版本，需自行复测。
2. 在 Arduino IDE 打开 [`m0/motor_control/motor_control.ino`](../m0/motor_control/motor_control.ino)。在“工具”中选与实际 ESP32-C3 开发板相符的板型和 USB 串口，然后编译、上传。
3. 打开串口监视器，设置 **115200** 波特率，发送一行 `PING`（以换行结尾），应收到 `PONG`。
4. 发送 `RUN LOW`，观察电机是否短时转动；发送 `STOP`，确认停转。若没有转动，先检查电源、接线和电机五针插头，不要直接试高速。
5. **关闭串口监视器**，再运行下一步的 Python 程序；两者不能同时占用同一个串口。

固件也接受 `RUN MEDIUM`、`RUN HIGH`、`RUN XHIGH` 和 `RUN ULTRA`。这些名称对应固件里的**步进间隔**，不是对你那台电机实测得到的转速。不同减速比、负载和安装方式会影响实际效果。

## 4. 接入本地 Codex

下载本仓库代码，在 Mac 的终端进入仓库根目录，先检查 Python：

```sh
python3 --version
python3 m1/global_bridge.py --once
```

`--once` 只显示桥接器识别到的本地任务状态，**不会连接电机**。没有正在运行的任务时显示 `STOP` 是正常的。接着运行：

```sh
python3 m1/global_bridge.py
```

保持这个终端窗口打开，在 Codex 中启动一个**本地**任务。桥接器会从当前用户的本地 Codex 任务记录读取任务开始、结束及推理强度，把状态映射为串口命令，并自动寻找会回应 `PING` 的 ESP32。终端出现 `Motor connected` 和 `Motor: RUN ...` 后，应能看到电机转动。按 **Ctrl+C** 退出时，桥接器会发送 `STOP`。

如果电脑连接了多个相似串口设备，可用 `--port` 指定实际端口，例如：

```sh
python3 m1/global_bridge.py --port /dev/cu.usbmodemXXXX
```

其中 `XXXX` 只是示例，**不要照抄**；以你电脑上实际出现的设备名为准。需要开机登录后自动运行时，再按 [`m1/README.md`](../m1/README.md)安装 macOS 用户服务。建议先完成终端试运行，再设置自动运行。

### 它如何与 Codex 相连？

```text
本地 Codex 任务记录 → Mac 上的 Python 桥接器 → USB 串口 → ESP32-C3 → ULN2003 → 电机
```

使用本教程**不需要 OpenAI API 密钥**。桥接器在本机读任务状态并向 USB 串口发命令，不把聊天内容上传到本项目的服务器。请勿把自己电脑中的 Codex 任务记录或日志上传到 GitHub；这类文件可能包含私人内容。

## 5. 哪些部分可以复用？

- **可直接尝试：** 同类 ESP32-C3、ULN2003、5 V 28BYJ-48、电源与接线条件下的[固件](../m0/motor_control/motor_control.ino)；macOS 本地 Codex 的[桥接器](../m1/global_bridge.py)及[安装器](../m1/install_macos.py)。脚本按当前用户的 `CODEX_HOME`（默认 `~/.codex`）寻找任务记录，并自动探测串口，没有写死作者的用户名或端口号。
- **需要按实物调整：** 开发板的引脚、不同电机的驱动方式和速度、花朵结构与供电。若换成四线双极电机或其他驱动板，不能原样使用这份 ULN2003 固件；可保留 `RUN ...`／`STOP` 串口协议，重写电机驱动部分。
- **尚未适配：** Windows 串口连接和服务安装、云端 Codex 任务、其他 Codex 客户端或未来可能变化的本地转录格式。OpenAI [Hooks 文档](https://learn.chatgpt.com/docs/hooks)明确说明转录格式不是稳定接口；本桥接器读取其中的推理强度属于当前版本可用的实现方式，升级 Codex 后需要复测。Codex 的 Local 和 Worktree 任务在本机运行，Cloud 任务在远端运行，详见 [OpenAI Docs 的运行环境说明](https://learn.chatgpt.com/docs/environments/modes)。

如果你的环境不在已验证范围内，可以按这个思路移植：先让电脑能识别 ESP32 串口并手动发送 `PING`／`RUN LOW`／`STOP`；再为你使用的 Codex 运行环境实现“任务开始、结束、推理强度”状态来源；最后把状态映射到相同串口命令。没有可靠的推理强度来源时，也可以先只实现“运行时转动、结束时停止”的两态版本，不必猜测速度档位。

## 6. 遇到问题

| 现象 | 先检查 |
| --- | --- |
| Arduino IDE 看不到串口 | USB-C 是否为**数据线**；线和转接器是否正常；开发板是否通电。 |
| `PING` 没有收到 `PONG` | 板型、串口、波特率和上传是否正确；串口监视器是否以换行结束。 |
| `PING` 正常但电机不转 | 先断开 USB，再检查 6 根线、驱动板电源正负和电机五针插头；重新接上后只试 `RUN LOW`。 |
| 桥接器找不到电机 | 先关闭 Arduino 串口监视器；检查 USB 串口是否变化；必要时传入 `--port`。 |
| 电机会转，但 Codex 任务没有触发 | 确认运行的是**本地**任务；用 `--once` 观察状态；检查 Codex 升级后转录格式是否变化。 |

更详细的原型测试记录与限制见 [`debug_log.md`](../debug_log.md)。
